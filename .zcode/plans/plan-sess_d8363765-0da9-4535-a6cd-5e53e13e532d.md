## 需求與理解修正

讀完 `slave new`：它是**真正的項目**，有完整硬體層（`driver/`16 驅動 + `lib/` hw_manager/sys_bus/TFT + `tasks/` control_panel 把編碼器/按鈕存到 `bus.shared`）。**目前無 LVGL UI**。

→ `ui/` 是 slave new 裡的**一個 UI 區塊**（像 tasks/lib），純 UI 邏輯，硬體透過 bus 對接。**不建 ui/hw/**（用戶說「假設我什麼都有」）。

## 需求 1：ui/ 純 UI 區塊 + src 進 ui/（板上部署結構）

```
design/{項目}/lvgl/
└── ui/                    ← 板上根目錄(只上傳這一個,放 slave new 專案根)
    ├── __init__.py        ← package import
    ├── app.py registry.py launcher.py ui_common.py
    ├── board.py           ← 對接 slave new 的 bus(改寫,非自帶 FrameBuffer)
    ├── page/…
    └── src/               ← 資源(原 lvgl/src → lvgl/ui/src)
        ├── icons_16.bin lv_icons.py zh_hant_16.bin lv_ui_fx.py
```
- `designlib.lvgl_src_path` → `lvgl/ui/src`
- `ui_common.py` 的 `from lv_icons/lv_ui_fx` → `from src import …`（fallback 根目錄）
- `lv_icons.py` 的 `_FONT_FILE` → `/ui/src/icons_16.bin`（或依產出位置）

## 需求 2：硬體不建 ui/hw/，改 board.py 對接 slave new bus

`ui/board.py` 改為「slave new 對接層」（不再 import mp_LVGL 根目錄的 lvgl_shared）：

```python
# ui/board.py — 對接 slave new 的 bus 系統
# 顯示: bus.get_service("lcd")（ST7789 + SpiBusAdapter）
# 編碼器: bus.shared["_enc_delta"]（control_panel 寫入）
# 按鈕: bus.shared["_vbtn"] / _vbtn1_event（VBTN 虛擬按鈕）
```

依 slave new 實況調整：
- lcd service 有 `set_window`/`write_data_async` → LVGL flush 對接（沿用 lvgl_shared 既有做法）
- 輸入從 bus.shared 讀（enc_delta 累加、vbtn 按鍵事件）
- **保留 platform 介面**（app 吃 {tick,take,show,enc_delta,confirm,exit}），讓「板載 bus 版」與「模擬器版」共用同一套 app/頁面

## 需求 3：代碼區動態 + 模擬輸入 + ui 框架執行（模擬器跑純 UI）

實測確認：模擬器能跑**純 LVGL UI**（lv.button/screen_load/anim_t 全可用），但 `machine` 被封鎖、package import 需 `ui/__init__.py`。

- **切頁連動**：點頁面按鈕 → 代碼區載入該頁 simcode
- **模擬輸入按鈕群**：`[◀ 旋轉][確認][▶ 旋轉][返回]` → 前端按鈕 → 注入模擬 platform
- **ui 框架模式**：代碼區切「單頁展示碼 / ui 框架」
  - 框架模式啟動碼：`sys.path` 掛 design/lvgl → `import ui.app` → 注入**模擬 platform**（SDL display + 前端按鈕→process_char→模擬輸入）→ run()
  - 模擬輸入管道：前端按鈕 → `iframe.contentWindow.process_char()` → MPY stdin → 模擬 platform 輪詢

## 實作步驟
1. `designlib.py`：lvgl_src_path → ui/src；lvgl_status 對應
2. `uiframe.py`：
   - 加 `ui/__init__.py`
   - `board.py` 改寫成 slave new bus 對接版（含顯示/編碼器/按鈕讀取）
   - 加 `ui/sim_platform.py`（模擬器用,不碰 machine）
   - `ui_common`/`lv_icons` 改 src import
3. server：designs 狀態更新；simcode 加 page + framework 模式
4. 前端：切頁連動 + 模擬輸入按鈕 + 模式切換
5. 重新生成 → 驗證 ui/ 無外部 import（純 UI + bus 對接）
6. 瀏覽器實測：框架模式 import ui.app + 跑起來 + 按鈕輸入

## 風險與因應
- slave new 的 bus 介面細節（lcd set_window、enc_delta/vbtn 格式）實作時確認,必要時調整 board.py 讀取
- 模擬器 stdin 管道不穩 → fallback 前端鍵盤映射（←/→/Enter/Esc）
- ui/board.py 只服務 slave new（import lib.sys_bus），模擬器不載入它（用 sim_platform）
